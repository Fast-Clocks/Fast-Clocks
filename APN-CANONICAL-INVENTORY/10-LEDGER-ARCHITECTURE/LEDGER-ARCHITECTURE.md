# LEDGER ARCHITECTURE & APPEND-ONLY ASSESSMENT

**Scope:** `public.apn_ledger_events` in `apn-backbone-sydney` (`plhpjktkzsbfnltemhdl`). LIVE-DB + SRC evidence, read-only.
**Forbidden words** (per spec) avoided unless proven: *immutable, blockchain, notarised, trusted timestamp, identity verified, legally binding.*

## Actual end-to-end path (as deployed)

```
event source (Edge Fn / cron / authenticated inbox insert)
  → INSERT into apn_ledger_events
    → BEFORE INSERT trigger ledger_chain()  [sets prev_event_id + hash]
      → row stored (append-only; UPDATE/DELETE blocked)
        → read only via SECURITY DEFINER fns (recent_ledger / ledger_counts_public / lookup_verification)
          → BUT those fns are EXECUTE-granted to service_role only (no anon)
```

Not every stage in the Sovereign Engine doc exists here. There is **no** receipt table, Merkle root, Ed25519 signature, `verification_records`, or public anchor sequence in this project. Those belong to the separate "APN Ledger Trust" (Lovable) backend — **not in this account** (see CODEX-BACKEND-RECONCILIATION).

## Proposed hardening (PROPOSED — not executed; each is a Gate-B change proposal)
1. `REVOKE TRUNCATE ON public.apn_ledger_events FROM service_role;` (+ optional BEFORE TRUNCATE guard).
2. Add `pg_advisory_xact_lock(<ledger key>)` at the top of `ledger_chain()` to serialise head reads.
3. Introduce `hash_version` + a documented canonical serialisation (sorted-key JSON, explicit field order) so a row is reproducible off-platform.
4. Decide one chaining authority: keep the global trigger and remove Edge-Function hashing, OR switch to per-machine chains — not both.
5. Only after a privacy review, grant `EXECUTE` on the public-safe read fns to `anon` to create a real public verifier — or keep verification server-mediated by design.
